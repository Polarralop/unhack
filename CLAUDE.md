# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

Results hub for **fluorescence microscopy** cancer tests (mostly FISH): doctors share results; patients receive, understand and acknowledge them, and raise concerns. Currently a **clickable prototype on mock data**. See `README.md` and `docs/product-brief.md`.

@AGENTS.md

## Stack

Next.js 16 (App Router) + TypeScript + Tailwind CSS 4, Node 24, npm. Next 16 differs from older versions: check `node_modules/next/dist/docs/` before using unfamiliar APIs.

## Commands

- `npm run dev` starts the dev server on :3000
- `npm run lint` and `npm run build` must pass before committing

## Architecture (prototype)

- All state is client-side: `src/lib/store.tsx` (useReducer + localStorage), seeded from `src/lib/seed.ts`. `StoreProvider` renders nothing until it has loaded in the browser, so pages are effectively client-rendered.
- `cacheComponents` / `partialPrefetching` are off in `next.config.ts` because nothing renders on the server yet. Revisit when a backend lands.
- Pipeline: microscope capture → lab (`labStage`: `scoring` by a technologist → `signout` by a pathologist → `released`) → doctor review (`/doctor/review/[id]`, while `sharedAt` is unset) → patient. Doctors only see `released` results and never make the primary reading; images are never edited. Once shared, status = `stageOf()` in `src/lib/types.ts`: shared → opened → understood, plus separate concern and appointment states.
- `src/lib/assays.ts` is the catalogue of fluorescence assays (probes, images, outcomes, suggested patient wording); seed data and the capture simulator build results from it.
- Design tokens (colors, font) live in `src/app/globals.css` under `@theme`.

## Rules

- Never use or generate realistic-looking real patient data; mock data must be obviously synthetic.
- Never commit secrets or `.env*` files (except `.env.example`).
- Patient-facing copy must be plain-language, honest and non-alarming; avoid jargon or explain it. Results are about cancer: never imply a diagnosis a test can't make (e.g. a positive screening FISH is not a cancer diagnosis), and explain what "positive"/"negative" means for that specific test.
- Result outcome is `flag: "negative" | "positive"` (whether the test found the change it looks for), not good/bad.
- Results that may mean a new or changed cancer diagnosis set `discussInPerson: true`: patient wording stays non-explicit and urges them to come in whenever they can (`ComeInCallout`).
- Microscopy images in `public/demo-images/` are synthetic, generated by `npm run images`. Never add real microscopy images to the repo.
- Uploaded images live only in the browser's IndexedDB (`src/lib/imageStore.ts`): the original file untouched plus a viewable preview. Render images via `MicroscopyImg` / `useImageUrls`, never a raw `src`, so uploads work.
- Lab routes are split by role: `/lab/technologist` (upload, score) and `/lab/pathologist` (sign out). Each role only gets its own form; other stages are read-only.
- Prototype first: prefer simple, readable code over abstraction. Things will be refined later.
